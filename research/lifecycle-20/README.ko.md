# Dots 수명 주기 연구 — 2026-10-23

대상은 [#20](https://github.com/abruption/dots-tailscale/issues/20)입니다. 이벤트 전달과 복구 실행은 [#43](https://github.com/abruption/dots-tailscale/issues/43), watchdog과 외부 복구의 실행 조정은 [#44](https://github.com/abruption/dots-tailscale/issues/44)에서 추적합니다. [English](README.md)

이 기록은 현재 SSH에서 확인한 내용, 이전 외부 관측 기록, Dots가 보고한 실행 결과를 구분합니다. 특정 VM이 교체됐다거나, `/workspace` 전체가 보존된다거나, 무인 복구가 안정적으로 작동한다는 근거는 아닙니다.

## 이번에 직접 확인한 내용

2026-10-23에 새 SSH 연결이 엄격한 호스트 키 검증을 통과했습니다. 공개 호스트 키 지문은 기존에 독립적으로 확인한 지문과 같았습니다. 개인키, SSH 접속 허용 키 목록, 노드 상태 파일, 인증정보의 내용은 읽거나 해시하지 않았습니다. 공개 실행 소스 네 파일과 공개 소스 명세의 해시만 확인했습니다.

- 설치된 소스 네 파일과 명세는 로컬 Git 태그에서 얻은 **v0.4.0** 명세와 모두 일치했습니다. 설치 경로의 `setup.sh`는 릴리스의 `tailscale-setup.sh`, `shim/shim.py`는 릴리스의 `shim.py`에 해당합니다.
- 포함된 Tailscale 버전은 **1.102.4**입니다. 소켓을 명시한 로컬 상태 조회 결과는 **Running**이었습니다.
- SSH 실행 UID는 **1000**이고 PID 1은 **bwrap**으로 표시됐습니다. 이 SSH 환경에서는 소켓이 보였지만 PATH에 `/workspace` 경로는 없었습니다. 네임스페이스 식별 정보는 비공개로 비교했으며 공개하지 않습니다.
- 현재 부팅 ID는 10월 23일 복구 뒤 확인한 값과 같고, 단절 전 정상 환경의 값과는 다릅니다. 부팅 ID가 달라져도 재부팅, VM 교체, 플랫폼 복원 중 무엇이었는지는 구분할 수 없습니다.

## 이번 복구로 확인한 범위

담당 세션이 제공한 외부 기록에서는 10월 22일 **22:22:22 KST**에 마지막 정상 SSH·ping, **22:23:27**에 첫 실패를 확인했습니다. 그러나 감시 전달기는 서버가 살아 있는 동안에도 그보다 앞선 **21:24**부터 관측을 보내지 못했습니다. 운영자의 SSH 재인증 뒤 10월 23일 복구 이벤트가 전달됐습니다. Dots는 권한 변경 금지 지시와 정상 시작 절차의 권한 복구가 충돌해 처음에는 claim을 받기 전에 중단했습니다. 지침 수정과 재개 요청 뒤 **09:33:49**에 claim을 받고 시작 명령을 한 번 실행해 성공했다고 보고했습니다. 외부 관측에서는 **09:34:25**에 새 SSH·ping의 정상 복귀를 확인했습니다.

사람이 개입한 뒤 Dots 쪽에서 연결을 복구하는 경로는 확인했습니다. 완전한 무인 복구가 입증된 것은 아닙니다. HTTP 200은 이벤트 수신만 뜻하고, Dots의 성공 보고는 외부 연결 복구를 뜻하지 않습니다. 새 관측이 없다고 정상으로 간주해서도 안 됩니다. 원래 시각과 실행 근거는 #43에 있으며, 이 문서는 이를 대신해 실시간으로 재시험한 기록이 아닙니다.

앞서 의도적으로 중지한 로컬 watchdog이 스스로 다시 시작할 것으로 기대하지 않았습니다. 과거 heartbeat의 `running` 값은 부팅 ID와 현재 프로세스 신원이 일치하지 않으면 과거 기록일 뿐입니다. watchdog의 최초 시작과 실행 예산 조정은 #44에서 다룹니다.

## 다음 관찰 계획과 한도

아래는 제안입니다. 이번 작업으로 새 데몬, 예약 작업, 상시 수집기를 설치하거나 장애를 주입하지 않았습니다.

1. **24시간** 관찰하고 끝에 명시적으로 검토합니다. 기존 60초 외부 감시를 사용하고 **5분**마다 프로세스·로그 크기를 측정합니다. 원격 명령은 각각 **15초**로 제한합니다. 공개 메타데이터와 집계한 연결 결과만 보관하며 비공개 원시 환경정보나 상태 출력은 남기지 않습니다.
2. 이번 관찰에서 내보내는 근거는 **총 10 MiB**로 제한합니다. 요약을 순환 보관하되 장애 경계는 유지합니다. 한도에 도달하면 추가 수집기만 멈추고 관찰이 불완전함을 기록합니다. 실행 중인 복구 서비스는 자동으로 중지하지 않습니다.
3. 수동적인 관찰 중에는 장애를 주입하지 않습니다. 기존 외부 정책인 최근 24시간 **최대 3회**, **1시간** 간격, 장애당 claim 한 번을 유지합니다. 이는 외부 실행 예산이며 향후 watchdog까지 합친 전역 한도는 아닙니다. 결과가 불명확하면 추측해 재시도하지 않습니다.
4. 호스트 키 변경, 소스 검증 실패, 필요한 인증 상태·신원 누락, 확인할 수 없는 실행 환경, 불확실한 관측 신선도·실행 권한이 있으면 새 복구 시도를 중단하고 운영자에게 알립니다. 시험을 통과시키려고 신원을 재생성하거나 재설치하지 않습니다.
5. 구성요소별 **RSS 256 MiB**, **스레드 128개**, **파일 디스크립터 512개** 또는 런타임 로그 합계 **50 MiB**를 넘으면 추가 능동 점검을 멈추고 검토를 요청합니다. 이는 실험 한도이며 입증된 제품 한계가 아닙니다. 자동 재시작이나 로그 삭제 대신 초과 사실을 기록합니다.
6. 전달, 이벤트 수신, claim, 시작 결과, 독립 SSH·ping을 각각 기록합니다. 자연 장애가 없으면 **24시간 정상 관찰**로만 보고하고 자동 복구·환경 전환 조건은 미검증으로 남깁니다. 장애가 있었다면 전체 시간대별 기록과 사람의 개입 여부를 보존합니다.

### 제한된 수집기

`collector.py`는 위 계획의 자원 관찰 부분을 구현합니다. 배치 여부와 실제 관찰 시작 시각은 운영자가 따로 기록합니다. 앞의 기준 측정은 이 수집기의 24시간 결과가 아닙니다.

`config.example.json`을 저장소 밖의 운영자 소유 **0600** 비공개 파일로 복사합니다. `ssh_host`와 명시적인 `ssh_hostname`을 이전에 검증한 연구 대상으로 정하고 `data_dir`에는 기존 **0700** 비공개 디렉터리를 지정합니다. 설정에 인증정보를 넣지 마세요. 수집기는 기존 로컬 SSH 인증과 엄격한 known-host 검증을 사용하며 추가 SSH 옵션을 받거나 신뢰 파일을 바꾸지 않습니다.

```sh
python3 collector.py --config /absolute/private/collector.json --once
python3 collector.py --config /absolute/private/collector.json
```

첫 실행은 대상에 접속하기 전에 최초 24시간 종료 시각을 저장합니다. 두 번째 실행은 같은 종료 시각을 사용해 재개합니다. `--duration SECONDS`는 새 실험을 최대 86,400초 범위에서 더 짧게 잡는 옵션이며 기존 상태의 종료 시각을 연장하지 않습니다. 관찰 기간을 몰래 늘리려고 상태 파일을 지우거나 다시 만들지 마세요. 별도로 승인된 후속 관찰에는 별도 데이터 디렉터리를 사용합니다.

수집기는 파일 잠금을 유지하며 `state.json`을 원자적으로 저장하고 `samples.jsonl`을 0600으로 기록합니다. 기한이나 실험 한도에 도달하면 정상 종료합니다. 서비스 관리자는 정상 종료만을 이유로 다시 시작하면 안 됩니다. 설정·잠금·기존 상태·근거 파일은 모두 소유자만 접근하는 일반 파일이어야 하며 심볼릭 링크 입력은 거부합니다. 표본 파일은 10 MiB를 넘지 않습니다. 크기가 고정된 비공개 상태·잠금 메타데이터는 이 용량과 별도입니다.

각 원격 실행에는 `timeout 15s`, SSH 전체에는 20초 제한을 적용합니다. stdout을 조금씩 읽어 최대 65,536바이트만 보관하며 한도를 넘으면 SSH 프로세스를 즉시 종료하고 종료 처리를 마칩니다. stderr는 프로세스 경계에서 버립니다. 조건에 맞는 원격 프로세스가 32개를 넘으면 일부만 남긴 정상 표본 대신 실패한 점검으로 기록합니다.

기준 소스 해시와 버전은 첫 성공 표본과 부팅 해시가 바뀐 뒤에만 수집합니다. 이후에는 자원 메타데이터, 가동 시간, 파일·소켓 존재 여부와 BackendState만 받습니다. 비공개 부팅 UUID는 전송 전에 해시합니다. 명시된 공개 소스 경로만 해시하며 심볼릭 링크인 소스는 거부합니다. 로컬에서는 정의된 스키마에 맞는 필드만 남깁니다. SSH stdout·stderr 오류 원문은 기록하지 않으므로 인증 URL이나 비공개 진단 대신 일반 오류 분류만 남습니다. SSH 실패가 복구 명령 실행으로 이어지지는 않습니다.

관련 오프라인 검증 명령은 다음과 같습니다.

```sh
python3 -m unittest discover -s research/lifecycle-20 -p 'test_collector.py' -v
```

이 검증은 종료 시각 보존, 부팅 추적, 자원·근거 용량 제한, 비공개 파일 안전성, 민감정보 제외를 다룹니다. 실제 장기 관찰의 완료나 플랫폼 전환 재현을 입증하지 않습니다.

## #20의 완료 조건

다섯 주제마다 범위가 정해진 재현 절차, 소스 버전, 실제 결과, 한계, 연결된 영어·한국어 안내가 필요합니다. 환경 전환은 관측으로 확인한 범위 안에서만 설명합니다. 남은 장기·플랫폼 전환 관찰은 미검증으로 유지하거나 명시적인 후속 이슈로 분리해야 하며 검증한 것으로 세면 안 됩니다. #43은 무인 인증·전달·실행의 남은 조건을, #44는 로컬·외부 실행 조정을 별도로 완료해야 합니다. 이 기준 측정만으로 어느 이슈도 완료되지 않습니다.
