# v0.6.0 release preparation

This candidate combines merged [PR #49](https://github.com/abruption/dots-tailscale/pull/49) and [PR #51](https://github.com/abruption/dots-tailscale/pull/51). Preparing this document does not publish the release or deploy it to an existing installation.

## Changes

- `dots-ts runtime check`, `apply`, and `status` provide explicit manual updates of the installed Tailscale CLI/daemon pair. Downloads or private offline bundles are bounded and validated before cutover. A detached worker, shared operation lock, persistent fence and journal preserve recovery information when SSH disconnects.
- Successful cutover preserves existing node state, SSH identity, shim/OpenSSH and configuration. Once candidate daemon execution is attempted, uncertain failure requires manual recovery; automatic state downgrade is not assumed safe.
- The separately deployed research relay preserves sanitized worker errors, exit codes and runtime diagnostics. A successful delivery clears current errors while transition records retain the previous failure. Installing the standard package does not deploy this relay.

## Installation and upgrade

Keep all four executable sources and the original `source-manifest.json` together. Use the [usage guide](../usage.md#update-management) to install the matching v0.6.0 tools before using the [runtime updater](../runtime-updates.md). An older installation must not be operated on using only a new checkout's CLI.

The default installation pin stays at **Tailscale 1.102.4**. Existing package updaters reject changes to the declared binary version; retaining that pin allows the new tool to be installed first. Updating the source package does not update the Tailscale binaries. After reviewing the current official stable version, use `runtime apply --version ... --confirm-recovery-terminal` explicitly. A fresh installation also starts with 1.102.4 until explicitly upgraded. Raising the default pin requires a separately validated migration.

Open an independent cloud terminal and pause any external recovery jobs before runtime cutover. After local success, verify fresh external SSH/ping and any application paths you need before resuming those jobs. No automatic update schedule or watchdog is enabled.

## Evidence and limits

- Both merged PRs received completed Codex code and security reviews without findings ([#49 review](https://github.com/abruption/dots-tailscale/pull/49#issuecomment-6405593828), [#51 review](https://github.com/abruption/dots-tailscale/pull/51#issuecomment-6408341777)). PR #51 also passed the requested independent Claude Code/Codex CLI review before creation. Its later live-validation commit changed documentation only.
- PR #51's executable candidate `2ef1c77` passed [327 core tests](https://github.com/abruption/dots-tailscale/actions/runs/40269034841) on Linux Python 3.11 and 3.13, including 71 runtime fixtures. The [isolated artifact smoke](https://github.com/abruption/dots-tailscale/actions/runs/40264987487) verified official 1.102.4 and 1.104.2 archives and real version-only outputs without network access or host/state mounts in the probe containers.
- The [2026-10-26 live trial](../validation/runtime-update-trial-20261026.md) installed the development candidate and upgraded CLI/daemon from 1.102.4 to 1.104.2, preserving identities and recovering external SSH/ping. This single normal-path trial does not cover live failure injection, state downgrade, VM replacement or all future releases.
- The stable candidate changes package metadata and documentation, not the reviewed executable sources. Exact candidate checks, research checks and artifact smoke must pass before publication.
- Tailscale 1.104.2 is an observed tested version, not a claim of Tailworm remediation. Same-origin checksums establish consistency, not independent publisher-signature authentication.

## Deferred scope

[v0.7.0](https://github.com/abruption/dots-tailscale/milestone/6) tracks opt-in automatic updates (#31), watchdog/external recovery coordination (#44), and reproducible experimental recovery setup (#45). Lifecycle (#20), external MCP recovery (#43) and exit-node feasibility (#16) remain in [Research](https://github.com/abruption/dots-tailscale/milestone/7); their unresolved scope is not claimed by this release.
