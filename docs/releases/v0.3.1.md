# v0.3.1 release preparation

Release preparation record for v0.3.1. The implementation PRs and the integrated candidate were reviewed before publication. Tag creation, asset validation and publication follow the checklist below; installed environments require a separate explicit deployment.

## Release summary

v0.3.1 includes startup-readiness and execution-context diagnostics (#25/#26), together with three proxy/transport fixes from [PR #35](https://github.com/abruption/dots-tailscale/pull/35):

- **Startup readiness (#25):** wait for transient backend states within an overall deadline and distinguish authentication, approval and query failures.
- **Execution-context diagnostics (#26):** report read-only filesystem/access and socket visibility in the current context, with independent GUI-terminal guidance.
- **Proxy apply and recovery (#32):** open and validate the private log before stopping the current daemon. Replacement and rollback reuse the same descriptor even if the path changes.
- **CONNECT data preservation (#33):** forward raw tunnel bytes buffered with the upstream response exactly once and in order. For TLS interception on port443, reject unexpected pre-handshake bytes before reporting success rather than discard them.
- **WebSocket framing (#34):** reject masked/reserved-bit frames, invalid control frames, malformed lengths and continuation sequences before forwarding their payloads or sending pong. Valid fragmentation and interleaved control frames remain supported.

Tailscale remains **1.102.4**. Installation still requires all four source files together: `tailscale-setup.sh`, `shim.py`, `dots-ts` and `dots_proxy.py`. Installation state and keys must be preserved during staged upgrades.

## Verification and remaining scope

- [Implementation CI](https://github.com/abruption/dots-tailscale/actions/runs/39201120437) passed **157** tests on each of Python 3.11 and 3.13, plus Bash syntax/ShellCheck.
- [Combined candidate CI](https://github.com/abruption/dots-tailscale/actions/runs/39205008955) passed all **178** tests on Linux Python 3.11/3.13 after the explicit-login/approval follow-up. [PR #36 re-review](https://github.com/abruption/dots-tailscale/pull/36#issuecomment-6260462216) and [PR #38 re-review](https://github.com/abruption/dots-tailscale/pull/38#issuecomment-6260469116) reported no additional findings.
- Focused proxy tests: 34 total, one Linux-only skip on macOS; focused shim tests: 45 passed, on actual Python 3.8 and 3.13.
- [Codex review of the final implementation commit](https://github.com/abruption/dots-tailscale/pull/35#issuecomment-6259931703) reported no major issues. The Linux reset/EOF finding was addressed in `89e0f37`.
- Process-control tests use inert mocks and disposable files. Shim tests use isolated transports/socket peers. No live deployment or forced outage is established by these results.
- The current 24-hour watchdog experiment belongs to #20 and uses the installed v0.3.0 environment; its pending results are not v0.3.1 deployment evidence.
- **#25 and #26 are included.** [PR #36](https://github.com/abruption/dots-tailscale/pull/36) and [PR #37](https://github.com/abruption/dots-tailscale/pull/37) were reviewed, passed CI and merged before the release preparation PR.
- VM replacement recovery, permanent automatic startup and automatic updates are not provided. No full WebSocket text UTF-8/close-status validation or new frame memory limit is claimed.

- [ ] Package the reviewed tag only: `dots-tailscale-v0.3.1.zip`, `dots-tailscale-v0.3.1.tar.gz`, plus the four individual source files.
- [ ] Compare archive source bytes with the individual files; generate `SHA256SUMS` and attach it as the seventh asset. Exclude workspace state, local untracked files, credentials, certificates and logs.
- [ ] Create/review a draft release, attach the seven assets and publish only after its exact tag/asset digests and notes are checked.
- [ ] Verify public links, latest-release selection and uploaded asset hashes. Date the changelog using the actual publication date.

Suggested archive commands after the tag exists, in Bash with `set -euo pipefail` and a pre-created private absolute `artifact_dir`:

```bash
git archive --format=zip --prefix=dots-tailscale-v0.3.1/ \
  --output="$artifact_dir/dots-tailscale-v0.3.1.zip" v0.3.1
git archive --format=tar.gz --prefix=dots-tailscale-v0.3.1/ \
  --output="$artifact_dir/dots-tailscale-v0.3.1.tar.gz" v0.3.1
for file in tailscale-setup.sh shim.py dots-ts dots_proxy.py; do
  git show "v0.3.1:$file" > "$artifact_dir/$file"
done
(
  cd "$artifact_dir"
  sha256sum dots-tailscale-v0.3.1.zip dots-tailscale-v0.3.1.tar.gz \
    tailscale-setup.sh shim.py dots-ts dots_proxy.py > SHA256SUMS
)
```

Publishing does not upgrade Dots automatically. A deployed update needs its own staged backup/restart/rollback procedure and external strict-host-key SSH verification.
