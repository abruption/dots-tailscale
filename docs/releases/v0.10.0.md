# v0.10.0 — SSH port selection for new installations

This is a preparation-time snapshot. Confirm the [published release](https://github.com/abruption/dots-tailscale/releases/tag/v0.10.0) and its exact-tag provenance before installation; a tag alone is not publication.

## Changes

[#63](https://github.com/abruption/dots-tailscale/issues/63) and [#91](https://github.com/abruption/dots-tailscale/pull/91) add `DOTS_TS_SSH_PORT` for new installations. An explicit value such as 2222 works when permitted by the current kernel threshold. Omitted selection and legacy generated configurations retain port 22. One owned private `ssh-port.json` drives installer checks, generated loopback OpenSSH configuration, startup probes, doctor and source/runtime update checks.

The installer rejects malformed, reserved, proxy-conflicting or foreign-occupied ports. It does not change sysctl, gain root privileges, kill other listeners or silently choose a fallback. Settings, candidate support and file snapshots must agree before source replacement. Supported package updates still restart only the shim and preserve the SSH process, identity and selected setting.

## Upgrade compatibility

Strict checks intentionally reject unsupported custom sshd directives, unsafe file modes/hardlinks and ambiguous paths even on legacy port 22. **Before the first upgrade from v0.9.1 or older**, independently authenticate the original manifest and all four candidate sources with trusted verifier/roots, then run the [read-only candidate SSH precheck](../usage.md#new-install-ssh-port). Hold an enabled old automatic source updater during this transition and do not change configuration concurrently. The external precheck is not atomic with an old worker and does not retrofit the new guard into it. Stop on failure; do not overwrite state, SSH settings or keys to force migration.

Existing-port migration is not supported. Port selection does not authorize tailnet access: host-key onboarding and policy for the chosen port need separate review. No live Tailnet or external SSH trial is claimed. A configuration change after shim stop can require manual review without source replacement.

The declared Tailscale baseline remains **1.104.4**. Installed runtime binaries are separate from package updates; node state, authentication and SSH identity remain preserved. The v0.9.1 proxy-environment fix is retained; an already-running conflicting daemon still needs the separate [controlled recovery procedure](../proxy-environment.md).

## Validation and publication

As recorded in the [dated review and validation report](../validation/ssh-port-new-install-20261115.md) and [PR #91](https://github.com/abruption/dots-tailscale/pull/91), independent Claude Opus 5.5 and Gemini 4 Argon Medium reviews preceded #91. Required findings were corrected and reviewed again. Linux Python 3.11/3.13 each passed 601 offline tests with no skips, together with Bash syntax, ShellCheck, manifest and Python static checks. The [dated validation report](../validation/ssh-port-new-install-20261115.md) separates mocked cases, historical Darwin limitations and actual Linux CI. This preparation changes only version metadata and documentation relative to merged #91.

After the preparation PR is merged, run the exact stable-tag provenance workflow, independently verify manifest and both archives, verify all ten asset bytes/checksums, and publish the original candidate without rebuilding. Publishing does not install the package or deploy research services, change operating recovery policies or enable optional runners. Record exact-tag checks and any deployment separately.
