# v0.9.1 patch-release preparation

This is a preparation-time snapshot, not publication or deployment evidence.
Verify the [published release](https://github.com/abruption/dots-tailscale/releases/tag/v0.9.1)
and its exact-tag provenance before installing. A tag alone is not publication.

## Fix

Issue [#89](https://github.com/abruption/dots-tailscale/issues/89) records a Dots
control connection failing with HTTP 403 and `NoState` because inherited lowercase
proxy variables bypassed the required local shim. Startup now sets both spellings
of HTTP/HTTPS proxy variables. Restart guards reject conflicting lowercase aliases
before proxy apply or runtime binary replacement; absent/empty legacy aliases are
normalized for candidate and rollback launches.

Only `tailscale-setup.sh` and `dots_proxy.py` change among the four executable
sources relative to v0.9.0. The declared Tailscale baseline remains **1.104.4**.
This package does not replace an installed 1.104.5 runtime, state, SSH identity,
application proxy ports, budgets or recovery permissions. Post-v0.9.0 translated
safety-guidance corrections (#88) are also included.

## Existing installations and limits

A package update does not change an already-running daemon's environment. Existing
update health guards remain in place. An affected unhealthy installation needs the
[controlled recovery procedure](../proxy-environment.md) first, followed by the
verified package update. Do not reset state, delete fences or downgrade binaries.
A future VM/session may inherit the conflicting platform variables again until
the corrected source has been installed and used to launch the daemon.

The maintainer's 2026-11-12 manual environment-cleanup/restart restored health using
the existing v0.9.0 package. That is cause/recovery evidence, not a live deployment
trial of this candidate. Isolated shell/process fixtures verify environment
selection and restart guards; they do not prove Internet control connectivity or
unattended/VM-replacement recovery. Record any candidate trial separately.

## Publication gates

Run the exact stable-tag provenance workflow after merge. Independently verify the
original manifest, both source archives, source hashes and all ten final assets;
publish the original candidate bytes without rebuilding. Follow the

separate operations. New opt-in features remain disabled by default.
