# v0.7.1 — 2026-10-29

This security release fixes [GHSA-84m8-25vr-f74m](https://github.com/abruption/dots-tailscale/security/advisories/GHSA-84m8-25vr-f74m):
the transport shim used the CONNECT host, unvalidated, in local certificate
cache paths and certificate identity fields. Severity is **Low**
(CVSS 3.1 `AV:A/AC:H/PR:L/UI:N/S:U/C:N/I:L/A:L`, 3.7). **v0.1.0 through v0.7.0
are affected.**

## What was wrong

For a CONNECT to port 443, the shim generated a leaf certificate for the
requested host and named the cache files after that host. A host containing
`../` or an absolute path selected files outside the shim's `certs` directory.
The shim then created those files, or overwrote existing ones with a newly
generated random private key. The fixed suffixes `.crt`, `.key`, `.ext` and
`.crt.csr` were always appended, and the parent directory had to exist and be
writable by the shim process.

The shim generates the certificate only after the upstream proxy accepts the
CONNECT. Whether the Dots platform proxy accepts such a host was not tested.

The listener is bound to `127.0.0.1`. However, tailscaled runs with
`--tun=userspace-networking`, which forwards inbound tailnet TCP for the node
address to the same port on `127.0.0.1`. Tailnet peers whose ACL permits port
18089 can therefore reach the shim, as well as local processes.

The issue does not allow remote code execution, a trusted misissued
certificate, or disclosure or replacement of the local CA key. A crafted host
containing `/` never produced a signed certificate, and the existing CA files
were never overwritten.

## Update

v0.7.0 declares the same Tailscale baseline (1.104.4), so use the ordinary
package update. Verify an independent cloud recovery terminal first:

```bash
/workspace/.dots-tailscale/dots-ts update check --tag v0.7.1 --proxy http://browser-proxy:8889 --json
/workspace/.dots-tailscale/dots-ts update apply --tag v0.7.1 --proxy http://browser-proxy:8889 --confirm-recovery-terminal --json
```

`update apply` replaces the four sources and manifest and restarts only the
shim, so the fix takes effect when the transaction completes. Tailscale
binaries, node state and SSH keys are not changed.

Packages declaring Tailscale 1.102.4, including v0.6.0, follow the
[explicit baseline migration](../security-baseline.md) directly to v0.7.1.

**Until you update:** if your tailnet policy allows every port to this node,
restrict it to the ports you use, for example SSH on 22. Peers that cannot
reach port 18089 cannot reach the shim.

## Changes and compatibility

- The shim validates the CONNECT target before dialing upstream. It accepts
  hostnames (letters, digits and hyphens in each label). It also accepts
  bracketed IPv6 literals, but not on port 443. Ports must be 1–65535 without
  leading zeros. Other targets receive `400 Bad Request`, and the log does not
  echo the rejected text.
- Cached leaf certificates are named by the SHA-256 of the host, so request
  text never becomes part of a filesystem path. The certificate generator also
  re-checks the host itself.
- Hostnames used for Tailscale control and DERP are unchanged. Each cached
  certificate is regenerated once under its new name after the update. Old
  host-named files in `shim/certs` are left in place and are no longer used.
  The local CA and `bundle.crt` are unchanged.
- Of the four executable sources, only `shim.py` changes. `tailscale-setup.sh`,
  `dots-ts` and `dots_proxy.py` are identical to v0.7.0.

## Validation

- New regression tests (`tests/test_shim_cert_host.py`) fail against the v0.7.0
  shim and pass with the fix. They cover rejection before upstream dialing,
  rejection before any file creation, preservation of an existing file outside
  the certificate directory and of the CA key, and certificate reuse.
- The source candidate passed 364 core tests on each Linux Python 3.11/3.13.
  The one failure, which also occurs on v0.7.0, came from the arm64 test host
  rejecting compiled x86_64 version probes. The shim tests also pass on
  Python 3.8.
- In an isolated container, the fixed shim answered crafted hosts with `400`
  before contacting a fixture upstream that accepts every CONNECT. It wrote no
  files outside its certificate directory, and an ordinary host still received
  `200` and a cached certificate.
- In an isolated tailnet (a private coordination server on a network without
  external access), a peer reached a loopback-only listener under userspace
  networking. A policy limited to port 22 blocked that reach.

These checks did not exercise the Dots platform proxy or a live Dots
installation. The GitHub Release links the final release commit's workflows.
