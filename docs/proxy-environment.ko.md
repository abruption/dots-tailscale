# 데몬 프록시 환경과 NoState 복구

[English](proxy-environment.md)

v0.9.1은 상속된 소문자 HTTP 프록시 변수 때문에 로컬 shim을 우회하는 문제를 수정합니다.
설치 전 공개된 배포 파일을 검증하세요. Tailscale 기본 버전은 1.104.4로 유지하며,
이 수정은 설치된 런타임 바이너리나 기기 신원을 바꾸지 않습니다.

## 확인된 원인

2026-11-12 사용자가 직접 실행한 Dots 점검에서 v0.9.0 소스 무결성과 CLI·데몬·백엔드
1.104.5는 정상이었지만 연결 상태는 `NoState`였습니다. 대문자 `HTTP_PROXY`·`HTTPS_PROXY`는
`http://127.0.0.1:18089`, 상속된 소문자 `http_proxy`·`https_proxy`는 플랫폼 프록시를
가리켰습니다. 데몬 로그에서 실제로 플랫폼 프록시를 선택한 것을 확인했고 제어 연결은
HTTP 403으로 실패했습니다. 소문자 변수를 제거하고 기존 상태를 유지한 채 확인된 데몬을
재시작하자 `Running`·인증 완료·정상 진단으로 복구됐습니다.

Tailscale v1.104.5가 사용하는 `golang.org/x/net` v0.60.0의
[환경 변수 선택 코드는 소문자를 우선합니다](https://github.com/golang/net/blob/v0.60.0/http/httpproxy/proxy.go#L75-L89).
장애 중에도 두 경로의 일반 HTTPS `/key` 조회는 200이었습니다. 이 조회만으로 제어 연결의
프로토콜 전환까지 검증할 수는 없습니다. 모든 403이나 `NoState`의 원인이 같거나 인증 정보가
사라졌다는 뜻도 아닙니다.

## 수정 동작

- 시작할 때 `HTTP_PROXY`·`HTTPS_PROXY`·`http_proxy`·`https_proxy`를 모두 로컬 shim으로
  맞추고 설치된 CA 묶음을 지정합니다. 스크립트의 자식 프로세스에만 적용하며 부모 셸이나
  전역 프록시 설정은 바꾸지 않습니다.
- 프록시 적용과 수동 런타임 업데이트는 비어 있지 않은 소문자 변수가 다른 프록시를 가리키면
  기존 데몬을 멈추거나 바이너리를 교체하기 전에 중단합니다. 기존 대문자 변수·CA 검사도
  유지하며 오류에 변수 값을 출력하지 않습니다.
- 소문자 변수가 없거나 빈 이전 설치는 허용하고 새 프로세스에서 값을 통일합니다. 후보 실행과
  원복 실행은 같은 검증된 환경을 사용합니다.
- 애플리케이션 SOCKS·HTTP 리스너, 업데이트 다운로드 프록시, 상태·키·업데이트 예산·복구 권한은
  바꾸지 않습니다. `NO_PROXY` 등 제외 규칙을 재설계하는 수정은 아닙니다.

## 기존 설치 복구

소스 업데이트는 이미 실행 중인 데몬의 환경을 바꾸지 않습니다. 일반 패키지 업데이트의 정상
상태 사전 점검도 유지합니다. 기존 데몬이 `NoState`라면 먼저 복구한 뒤 검증된 v0.9.1을
적용하세요. 이 문제를 우회하려고 상태 삭제·로그아웃·강제 재인증·바이너리 다운그레이드를
진행하지 마세요.

Tailscale 연결이 일시 중단되므로 별도의 클라우드 컴퓨터 터미널에서 진행합니다. 상태 파일
내용을 출력하지 않고 실제 선택한 프록시와 프로세스를 확인하세요.

```bash
/workspace/.dots-tailscale/dots-ts doctor
grep -F 'tshttpproxy: using proxy' /tmp/dots-tailscale-$(id -u)/tailscaled.log | tail -n 5
ps -C tailscaled -o pid=,etimes=,stat=,comm=
```

로그를 공유하기 전 자격정보가 포함된 URL은 가리세요. PID·UID·실행 파일·상태 디렉터리·소켓이
해당 설치와 일치하는지 확인합니다. 이름만 보고 모든 tailscaled를 종료하거나 소켓을 임의로
지우지 마세요. 패키지·런타임 업데이트나 복구 작업이 진행 중이면 그 상태부터 확인하고,
진행을 위해 업데이트 차단 표시를 삭제하지 마세요.

확인된 데몬을 정상 종료하고 실제로 사라졌는지 확인한 뒤, 상속된 소문자 변수를 제거해 기존
설치를 다시 시작합니다.

```bash
env -u http_proxy -u https_proxy bash /workspace/.dots-tailscale/start.sh login
```

이 환경 변수 지정만으로 실행 중인 데몬이 바뀌지는 않습니다. `login`은 강제 재인증 옵션 없이
`tailscale up`을 요청합니다. 예상치 못한 새 승인 URL이 나오면 기존 상태와 기기 신원을 확인하기
전에는 새 등록을 승인하지 마세요. 상태와 SSH 키는 계속 보존합니다.

```bash
/workspace/.dots-tailscale/dots-ts doctor
```

`Running`·인증 완료·소스 무결성 일치를 확인하고 외부에서 새로운 SSH 호스트 키 엄격 검증 접속과
Tailscale ping을 따로 확인합니다. 이후 [업데이트 안내](usage.ko.md#update-management)에 따라
출처가 검증된 공개 패키지를 적용하세요. 소스 원복은 런타임·상태 다운그레이드가 아닙니다.
위 복구는 사용자가 개입한 관측이며 무인 복구나 VM 교체 지원을 입증한 시험은 아닙니다.
