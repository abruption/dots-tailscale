## Isolated execution and concurrency evidence

The automatic-update control-plane tests use real forked workers, the
`apply_worker` acknowledgement, caller `submitted` state, durable execution
commit, journals and file locks. Positive commit, disable-before-commit and a new
recovery stop before commit are separate cases. The transaction body is a
non-installing fixture: these tests do not perform cryptographic verification,
replace a real installation, restart a daemon or contact a network. Linux uses
native process/boot observations; non-Linux POSIX tests adapt the Linux-specific
identity observation.

The shim admission tests use real socket pairs with **TLS explicitly replaced by
a socket/identity fixture**. They exercise capacity, cleanup, worker ownership,
long-lived stream behavior and parent wakeup; they do not validate an actual TLS
handshake, platform proxy behavior or production resource exhaustion. A negative
control removing the WebSocket worker's final shutdown made the wakeup regression
fail as expected, while the unmodified regression passed. The negative-control
harness returning zero records the expected test failure, not a successful run of
the broken implementation. See [shim-admission.md](../shim-admission.md).

The local recovery command and separately deployed MCP broker retain different
responsibilities. A broker claim, local exit zero, callback receipt and fresh
external SSH/ping are distinct evidence. The previous operator report of the
#61 cooldown deployment is historical operating evidence; this development work
has not newly verified that production deployment or a natural outage.
