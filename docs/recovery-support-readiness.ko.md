# 복구 미리보기: 대상 사용자, 설정과 공개 조건

[English](recovery-support-readiness.md)

이 문서는 #45를 위한 v0.8.0 개발 계획입니다. 일반 사용자에게 자동 복구가 제공된다는 뜻은 아닙니다. 첫 후보 경로는 **고급 사용자용 자체 호스팅 MCP Events 방식**입니다. HTTPS·브라우저 SSO/OAuth·외부 감시기·독립 Dots 클라우드 터미널을 유지할 수 있는 운영자를 대상으로 합니다. 기존 코드와 시험 기록으로 이 경로를 시험할 수 있지만, 모든 사용자에게 관리자의 서버나 브라우저 자동화 도구가 있다고 가정하지는 않습니다.

공유 예약 작업 링크는 별도 후보로 남아 있습니다. 공유 버튼이 있다는 사실만으로 다른 계정이 작업을 가져와 승인하고 새 클라우드 컴퓨터에서 실행할 수 있다고 볼 수는 없습니다. 이번 마일스톤은 ChatGPT 예약 작업을 설치하거나, 호스팅 중계기를 채택하거나, Worker를 배포하거나, 서버가 필요 없는 설정을 약속하지 않습니다.

## 무엇을 켤지 먼저 고르세요

| 경로 | 운영자가 준비할 것 | 현재 한계 |
|---|---|---|
| 클라우드 터미널에서 수동 시작 | 기존 설치, 남아 있는 state, 직접 터미널 접근 | 복구를 위한 기본 대안이며 이벤트·예약·watchdog이 필요하지 않습니다. |
| 패키지에 포함된 로컬 watchdog | 명시적 로컬 활성화, 보이고 쓸 수 있는 설치 경로와 소켓 | 같은 실행 환경에서 구성요소를 복구할 수 있지만 VM 교체 뒤 자신을 다시 시작할 수는 없습니다. |
| 자체 호스팅 MCP Events | 별도 HTTPS 호스트, OAuth/SSO, 감시, 앱 연결, 유지되는 구독 | 고급 미리보기입니다. 이벤트 수신과 실제 실행은 별도 단계이고 지연될 수 있습니다. |
| 공유 Dots 예약 작업 | 계정별 작업 승인, 검증한 클라우드 실행 환경 | 최초 지원 경로로 채택하지 않았습니다. 새 계정과 수명 주기 시험이 남아 있습니다. |

## 새 운영자의 설정 순서

1. 고정된 안정 패키지를 설치하고 소스 무결성, 실행 중인 Tailscale 버전, 기존 인증 state와 SSH 호스트 키를 확인하세요. 복구 동작을 바꾸기 전에 Dots 클라우드 터미널에 직접 접근할 수 있는지도 확인합니다. 관리자의 노드 state나 개인 키를 복사하지 마세요.
2. [고정된 연구 의존성](../research/mcp-events/requirements.lock), 전용 계정, 보호된 Unix 소켓을 사용해 별도의 Linux broker를 준비합니다. [실험 안내](experimental-recovery.ko.md), [보안 보완](../research/mcp-events/security-hardening.md), [서비스 템플릿](../research/mcp-events/services/README.md)을 따르세요. 이전의 loopback 배포 예시가 보안을 강화한 배포 절차를 대신하지는 않습니다.
3. 본인이 관리하는 호스트명과 SSO 신원을 사용합니다. 정확한 소유자 하나, issuer/resource, 공개 클라이언트, 승인된 ChatGPT redirect를 설정하세요. 프록시에서 호출자가 보낸 신원 헤더를 제거하고 인증 후에만 신뢰하는 신원으로 덮어씁니다. 실행 설정과 자격증명은 체크아웃 밖의 비공개 영속 경로에 두고 이슈에 붙여 넣지 마세요.
4. 사용할 ChatGPT 계정에서 사용자 지정 MCP 앱을 연결합니다. 운영자가 로그인과 명시적 동의를 완료하세요. 처음에는 읽기 전용 관측으로 시작하고 익명·다른 소유자·읽기 전용 토큰으로 claim이나 실행 보고를 할 수 없는지 확인합니다.
5. 별도의 외부 감시기와 전달기를 설정합니다. 서버가 확인한 표본이 계속 새로 들어오는지, SSH 인증·호스트 키 오류를 네트워크 장애로 취급하지 않는지, 구독 만료가 드러나는지 확인하세요. broker의 상태 엔드포인트나 callback HTTP 200이 정상이라고 Dots가 실행했다는 뜻은 아닙니다.
6. 조정 모드를 쓰려면 새 진입점을 거치지 않는 기존 watchdog이나 작업부터 중지하세요. 검토한 패키지를 설치하고 [복구 수명 주기 안내](recovery-lifecycle.ko.md)에 따라 로컬 복구 정책을 명시적으로 설정합니다. 별도 배포한 broker의 `recovery_local_coordination`을 `true`로 바꾸고 대상 작업의 지침만 조정용 템플릿으로 교체하세요. 양쪽이 준비된 다음 해당 작업을 켭니다. broker 기본 명령은 여전히 기존 경로이며, 패키지만 설치한다고 바뀌지는 않습니다.
7. claim을 받기 전에 새 로컬 상태의 `blocked_reason`과 `next_allowed_at`을 확인하세요. 로컬 정책이 실행을 막거나 실행 환경이 불명확하면 claim을 받지 않습니다. 참고 시각이 지났다고 허가가 생기는 것이 아니므로 지연 뒤에는 로컬·broker 상태를 새로 읽습니다. 새 실패 관측에 대해서만 새 claim을 사용하세요. 조정 모드에서는 고정된 명령과 인자, claim ID·만료 시각·관측 시각을 현재 승인된 broker 결과와 비교합니다. 로컬 명령은 구조·신선도·자체 영속 예산을 확인하지만, 명령 옵션이 OAuth 승인에 대한 암호학적 증거는 아닙니다. 작업은 승인된 앱에서 claim을 받아야 합니다. 임의의 이벤트 본문에 있는 명령을 실행하지 마세요.
8. 로컬 종료·결과, broker 보고, 새 외부 SSH·ping 관측을 따로 기록합니다. 종료 코드 0은 로컬 시작 성공입니다. 연결 복귀는 새로운 외부 증거로만 확인합니다. timeout이나 결과 불명은 원래 request ID로 대조해야 하며 새 claim이나 무작정 재실행으로 처리하지 마세요.

허용된 시작은 기존 노드 state와 SSH 신원을 유지합니다. 검토된 기존 시작 절차처럼 설치 디렉터리를 0700, 기존 민감 파일을 0600으로 맞출 수 있습니다. 일반적인 소켓·PID·로그 파일을 만들고 정상 state를 갱신할 수도 있습니다. 설치·로그인·재등록·state 삭제·키 교체·새 authorized key·소유권 변경·권한 확대·네트워크 정책 변경까지 허용하는 것은 아닙니다. 자동 업데이트는 별도 opt-in이며 복구 동의가 자동 업데이트 동의가 되지는 않습니다.

## 중지와 제거

대상 Dots 복구 작업·구독을 끄고 비활성 또는 만료 상태를 확인하세요. 아직 처리 중인 claim과 결과가 불명확한 로컬 시도를 살펴봅니다. 문서에 있는 명령으로 로컬 복구·watchdog을 끈 상태가 유지되도록 설정해야 하며, 외부 이벤트가 이 중지 의사를 취소해서는 안 됩니다. 실제 설치된 라벨을 확인해 전용 전달기·감시기·broker 단위를 각각 중지하세요. 비공개 claim과 시도 원장은 대조를 위해 보존하고, 차단을 풀려고 OAuth·claim DB를 초기화하지 마세요.

이 절차는 Tailscale을 중지하거나 독립 방화벽 보호를 제거하지 않습니다. 실행이 이미 확정된 작업은 끝날 수 있습니다. 이후 시도를 막는 설정을 이미 진행 중인 시작까지 취소하는 기능으로 설명하지 마세요.

## 근거와 공개 판단

| 조건 | 확인한 근거 또는 남은 작업 |
|---|---|
| 소유권, claim 1회 사용, 신선도, 계정 분리, 만료 | 오프라인 broker·HTTP 시험이 있습니다. 두 소유자를 분리한 새 DB 시험은 다른 실제 ChatGPT 계정의 연결 시험이 아닙니다. |
| 내부·외부 경합, 지속되는 중지, 예산과 결과 불명 차단 | 조정 수명 주기 시험으로 확인합니다. 운영 장애 주입이나 실제 VM 교체 시험은 포함하지 않습니다. |
| 도움을 받아 수행한 실제 이벤트 기반 시작과 외부 연결 | [#43](https://github.com/abruption/dots-tailscale/issues/43)과 [상시 시험 기록](../research/mcp-events/continuous-trial.md)의 날짜별 근거를 봅니다. 사람이 개입한 단계는 따로 구분합니다. |
| 새 계정으로 문서만 보고 연결·구독·진단·해제 | 별도의 실제 계정과 실행 환경이 필요합니다. 오프라인 시험이나 기존 관리자의 구독만으로 입증되지 않았습니다. |
| 지침 수정·재인증·명시적 재개 요청 없는 자연 장애 복구 | 시험별 감시·claim 근거를 날짜와 함께 판단합니다. 관측한 성공을 지연 시간 보장으로 확대하지 않습니다. |
| 새 VM·실행 환경과 장기 운영 | [#20](https://github.com/abruption/dots-tailscale/issues/20)·[#43](https://github.com/abruption/dots-tailscale/issues/43)의 연구로 남습니다. boot ID 변경만으로 VM 교체가 입증되지는 않습니다. |

**판단:** 개발 후보의 문서는 준비할 수 있지만, 실험 기능의 공개 조건이 충족됐다는 판정은 보류합니다. 실제 새 계정 재현과 수명 주기 조건이 충족될 때까지 #45는 열린 상태로 두고 고급 경로는 명시적으로 선택한 개발 미리보기로 한정합니다. 다른 실제 계정에서 연결·설정·복구·해제를 재현한 시험은 아직 완료하지 않았습니다. 일반 설치는 플러그인·구독·예약·watchdog을 등록하지 않아야 합니다. 실제 시험 전에는 관측 기간, 중지 조건, 독립 터미널, 성공 기준을 먼저 적고 실패와 수동 지원 사례도 남기세요. 즉시 실행, 모든 환경 교체 후 복구, 정해진 성공 횟수, 무인 서비스 가용성을 약속하지 않습니다.
